Execute an attribute callback

Resolves dynamic attribute content for the attribute identified in the request, using the supplied scope and current attribute values.

required

required

required

object (PaginationRequestDto)

Signature Formatting Provider

Signature Formatting Provider API defines operations for protocol-specific formatting of digital signing requests. The provider is stateless and handles the conversion between raw signing material and protocol-specific formats (e.g. TSA TimeStampToken). It serves the timestamping workflow; AdES content-signature formatting is served by the Content Signing Formatting contract at /v1/signatureProvider/contentSigning.

Assemble final formatted output

Authorizations:
ConnectorAPIKeyAuthCertificateTLSAuthNoAuthBasicAuth
Request Body schema: application/json
required
type
required
string (SigningWorkflowType)

Signing workflow type

dtbs
required
string <byte>

Data-to-be-signed bytes returned by formatDtbs (already contains serialNumber, signingTime, etc.)

signature
required
string <byte>

Raw signature bytes from the Cryptography Provider

certificateChain
required
Array of strings <byte> non-empty [ items <byte > ]

Certificate chain where the first element is the signer certificate

required
Array of objects (RequestAttribute)

Formatting-specific parameters, same attributes as passed to formatDtbs

serialNumber
required
integer

Serial number generated by Core, recorded in the Signature inventory

signingTime
required
string <date-time>

Signing time captured by Core from the time quality system

accuracy
string

Accuracy of the signing time, captured by Core from the time quality system (ISO 8601 duration, e.g. PT0.001S for 1 ms). Optional per RFC 3161 — absent when no Time Quality Configuration applies (e.g. a non-qualified local-clock timestamp).

signatureAlgorithm
required
string (SignatureAlgorithm)
Enum: "SHA256withRSA" "SHA384withRSA" "SHA512withRSA" "SHA256withRSAandMGF1" "SHA384withRSAandMGF1" "SHA512withRSAandMGF1" "SHA256withECDSA" "SHA384withECDSA" "SHA512withECDSA" "Ed25519" "Ed448" "FALCON-1024" "ML-DSA-65" "SLH-DSA-SHA2-128F"

Signature algorithm to be used for timestamping

hashAlgorithm
required
string (DigestAlgorithm)
Enum: "MD5" "SHA-1" "SHA-224" "SHA-256" "SHA-384" "SHA-512" "SHA3-256" "SHA3-384" "SHA3-512"

Hash algorithm used to produce the message imprint in the timestamp request

policy
string

TSA policy OID requested by the client

nonce
integer

Nonce from the timestamp request for replay protection

includeSignerCertificate
required
boolean

Whether the signer certificate should be included in the response

qualifiedTimestamp
required
boolean

Whether the timestamp is ETSI qualified electronic timestamp

Array of objects (ExtensionDto)

Extensions from the timestamp request

data
required
string <byte>

The hashed message (message imprint) — needed to rebuild the TimeStampRequest

Connector Info v2

Connector Information API. Each connector may have multiple functions represented by its connector interfaces. For each connector interface there is a list of implemented endpoints. These endpoints must be according the specified interface, this is validated by the core. You can also implement helper end points that are used for callbacks and other relevant operations specific to implementation.
