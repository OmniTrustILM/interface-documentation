ILM Documentation

Inspection

Reading uploaded files to report what they hold

Read an uploaded file

Report what an uploaded file holds, without importing or storing anything.

The file travels base64-encoded in file, like every upload in the platform, and is held in memory rather than written anywhere; it is never echoed in an error, since it may carry key material. Every container the platform understands is accepted, so a caller uploads once and then decides: PKCS#12 in any composition, a PEM bundle of certificates with at most one private key, a standalone PKCS#8 key, plain or encrypted, an OpenSSL traditional PEM key, an OpenSSH private key, a single certificate as PEM or DER, and PKCS#7. The container is recognised by its content, not by its file name. JKS and JCEKS stores are read too.

Nothing here has to be carried into a later operation. Each entry is reported with a reference derived from the entry's own content, so an operation given that reference acts on that content whichever file it arrives with. Read a file when a user should see what is inside before anything is imported; a caller that already knows what it is sending does not need to.

Request Body schema: application/json
required
file
required
string <byte> <= 6990508 characters

Content of the uploaded file, base64-encoded: a container such as PKCS#12 or PEM, a standalone key, or a certificate. At most 5 MiB decoded. The platform holds it in memory only, never writes it anywhere and never echoes it in an error, since the file may carry key material.

passphrase
string <password>

Passphrase that opens the uploaded file. Absent for a file that carries no protection of its own.

tokenProfileUuid
string

Token profile the caller intends to import key material into. When given, each entry is reported with whether that profile can hold it.
