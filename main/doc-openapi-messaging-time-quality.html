Time Quality Messaging

RabbitMQ message contracts between Core and Time Quality Monitor. These are not HTTP endpoints — the paths exist only to anchor each message schema in the generated OpenAPI document.

Time Quality Result [RabbitMQ: Monitor → Core]

Message published by Time Quality Monitor and consumed by Core. Carries the NTP check outcome — overall status, measured drift, per-server details — for a specific time quality configuration profile.

Request Body schema: application/json
required
configurationId
required
string <uuid>

UUID of the time quality configuration that produced this result

name
required
string non-empty

Display name of the time quality configuration

timestamp
required
string <date-time>

Timestamp when the check was performed, in ISO 8601 UTC format

status
required
string (TimeQualityStatus)
Enum: "ok" "degraded"

Overall time quality status. DEGRADED is always set when NTP leap indicators conflict across servers (LeapUnsync), regardless of the profile's leapSecondGuard setting

measuredDriftMs
number <double>

Measured clock drift from NTP reference time in milliseconds; null when drift could not be determined

reachableServers
required
integer <int32> >= 0

Number of NTP servers that were reachable during this check

reason
string

Human-readable reason for the resulting status, if applicable

leapSecondWarning
required
string (LeapSecondWarning)
Enum: "none" "positive" "negative"

Leap second warning derived from NTP leap indicators. Set to NONE when indicators conflict

required
Array of objects (NtpServerMeasurementResult) non-empty

Per-server measurement details for this check

Responses

Time Quality Config Snapshot [RabbitMQ: Core → Monitor]

Message published by Core and consumed by Time Quality Monitor. Carries a full snapshot of all active NTP-based time quality configurations; always a complete replacement, never a delta.

Request Body schema: application/json
required
correlationId
string <uuid>

Correlation identifier carried from the matching TimeQualityConfigRequest. Null when Core publishes the snapshot proactively.

generatedAt
required
string <date-time>

Timestamp when the snapshot was generated, in ISO 8601 UTC format

required
Array of objects (TimeQualityConfig)

Complete list of active NTP-based time quality configurations; always a full snapshot, never a delta

Responses

Time Quality Config Request [RabbitMQ: Monitor → Core]

Message sent by Time Quality Monitor to Core requesting a fresh snapshot of all active time quality configurations. Core responds by publishing a TimeQualityConfigSnapshot.

Request Body schema: application/json
required
correlationId
required
string <uuid>

Unique correlation identifier carried back in the matching TimeQualityConfigSnapshot so the requester can pair the response with this request

requestedAt
required
string <date-time>

Timestamp when the config request was sent, in ISO 8601 UTC format
